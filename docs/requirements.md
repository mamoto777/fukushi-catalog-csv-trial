# 要件定義書 v2 — 知人配布版(テンプレート入れ替え式カタログアプリ)

**作成日**: 2026-08-19
**ステータス**: 確定(/build パイプライン入力用)
**前提**: 本リポジトリは案件版(CSV取り込み)+かんたん版(Excel取り込み)の全タスクが完了・公開済み(https://mamoto777.github.io/fukushi-catalog-csv-trial/)。本書はその上に行う「v2改訂」の要件を定義する。

---

## 1. 背景・目的

### 1-1. 位置づけの転換(確定事項)

- 本アプリを「クライアント事業の試作」から**「知人がまず個人的に使ってみる、配布用のベースアプリ」**へ位置づけ直す
- 配布方法: **今のリポジトリ・今の公開ページ(GitHub Pages)をそのまま改訂**し、URLを知人に渡すだけで配布完了とする(新リポジトリは作らない)
- 実データ(商品・価格)は端末のブラウザ内にのみ存在し、リポジトリ・公開ページ・外部サーバーには一切載せない原則を**維持**する

### 1-2. 改訂の根拠(クライアント側意見・2026-08-19受領)

原文の要点(本書はこれを正とし、原文ファイルへの参照を不要とする):

- 主な使用場面: ①商品の仕様や価格を知りたい時 ②(特に新人が)利用者にどの商品を選んだら良いか困った時
- 商品情報に入れたい事: 仕様 / レンタル価格 / **TAISコード** / 製造メーカー / 商品特徴 / **類似商品(可能であれば)**。テクノエイド協会「福祉用具情報システム」の商品情報検索後の画面がイメージ
- 検索時のキーワード: **商品名** / 分類(車いす、手すり等) / **シーン別**(例:〈歩行器〉家の中で使用・買物で使用。分類の中でシーンを見る導線)
- 今後メンテナンスが必要な場面: 新商品の追加 / 廃盤商品の削除 / レンタル価格の見直し / **シーンの追加**

### 1-3. 「テンプレート入れ替え式」の定義(確定事項)

利用者が記入したテンプレートファイルを読み込むと、アプリの中身が**丸ごと入れ替わる**方式。入れ替え範囲は以下で確定:

- **商品データ**: 入れ替え可能(既存機能の継続)
- **シーン・困りごとの語彙**: 入れ替え可能(**本改訂で新規対応**。「シーンの追加」を利用者自身で完結させる)
- 分類(9ジャンル)・「誰が使う」の語彙: 固定(アプリ内蔵のまま。画像・画面構成と結合しているため)

新商品追加・廃盤削除・価格見直しは「テンプレートファイルが正本。直して読み込み直せば全置換で反映」という運用でカバーする(部分更新はしない)。

## 3. 機能要件

### FR-1: かんたん版Excelひな形の改訂(v2・10列)

`public/products-template-simple.xlsx` を以下の10列構成に改訂する(この順・この見出し文言で固定):

| 列 | 見出し | 入力方法 | 必須 | 対応するご意見 |
|---|---|---|---|---|
| A | `商品名` | 手入力 | 必須 | 商品名検索 |
| B | `メーカー` | 手入力 | 任意(空なら表示は「―」) | 製造メーカー |
| C | `分類` | プルダウン(9ジャンル日本語名) | 必須 | 分類検索 |
| D | `価格(円)` | 手入力(正の整数) | 必須 | レンタル価格 |
| E | `TAISコード` | 手入力(自由記述・形式チェックなし) | 任意 | TAISコード |
| F | `ひとこと説明` | 手入力 | 必須 | 商品特徴 |
| G | `仕様` | 手入力(1行1項目「項目名:値」形式。セル内改行区切り。全角コロン「：」も可) | 任意 | 仕様 |
| H | `困りごと1` | プルダウン(シーン設定シート参照) | 必須 | シーン別検索 |
| I | `困りごと2` | プルダウン(同上) | 任意 | シーン別検索 |
| J | `誰が使う` | プルダウン(本人が使う/家族の介護に使う/どちらも) | 必須 | — |

- サンプル行(2〜4行目)は新列構成に合わせて更新する。仕様列のサンプルには「重さ:290g」+セル内改行+「高さ調節:71〜94cm」のような**記入例として機能する値**を必ず入れる
- 仕様セルの検証: 空行は無視。コロン(半角:または全角：)を含まない行は行番号つきエラー(「N行目: 仕様 "◯◯" は「項目名:値」形式ではありません」)
- 自動補完(v1から変更となる点のみ): `maker` = B列(空なら `"―"`) / `taisCode` = E列(trim) / `specs` = G列の解釈結果(空なら `{}`)。それ以外(id自動採番・insurance="rental"固定・popularity=3固定・description=ひとこと説明と同文・sceneTags自動導出・userTags展開)はv1仕様を踏襲
- **v1ひな形(7列)との互換は持たない**。見出し検証で不一致とし、「ひな形が古い形式です。アプリから新しいひな形をダウンロードしてください」系の行番号つきエラーで案内する(知人はまだ利用開始前のため互換不要と判断)

### FR-2: シーン語彙の入れ替え(シーン設定シート)

かんたん版ひな形に**表示状態の「シーン設定」シート**を追加し、読み込み時に語彙(場面・困りごと)を再構築する:

- シート構成: A列=`場面`、B列=`困りごと`(1行1困りごと。同じ場面名を複数行に繰り返して書く)。1行目は見出し。初期値として内蔵vocab.jsonの全31行を機械転記する
- 利用者が行を追加・変更・削除すると、その内容がアプリの語彙(ナビの質問2・質問3の選択肢、場面の自動導出、シーン絞り込み)になる
- 検証規則(エラーはすべて「シーン設定シート N行目: …」形式):
  - 場面が空で困りごとのみある行 → エラー
  - 困りごとが空で場面のみある行 → エラー
  - **困りごとの重複禁止(全場面を通じて一意)** — 場面の自動導出が一意に決まるための必須条件
  - 有効行0件 → エラー
  - 上限: 場面12種・困りごと120行(ナビUIの破綻防止。超過はエラー)
- 商品リストの困りごと1・2は、**同じファイルのシーン設定シートの語彙**に対して検証する
- 困りごとプルダウン(H・I列)の参照範囲はシーン設定シートB列の120行分まで余裕を持たせ、**利用者がシーン設定シートに追記した語もプルダウンに現れる**ようにする
- シーン設定シートが存在しない .xlsx → エラーで新ひな形のダウンロードを案内
- 場面の並び順=シーン設定シートでの初出順。困りごとの並び順=シート内の行順
- `scripts/make_simple_template.py` を新構成(10列+シーン設定シート)に改訂し、ひな形とテストfixtureを再生成する

### FR-3: フル版CSVの改訂(v2・16列)

- ヘッダを `id,name,maker,taisCode,genre,price,insurance,summary,description,specs,recommendFor,caution,concernTags,sceneTags,userTags,popularity` の16列に改訂する(`taisCode` を `maker` の直後に挿入)
- `taisCode` は任意(空文字可・形式チェックなし・trimのみ)
- 旧15列ヘッダは既存の「ヘッダ行が想定と一致しません」エラーで自然に弾かれる(専用の互換処理は不要)
- `public/products-template.csv` を16列版に更新する(サンプル値のTAISコードは架空の値または空とする)
- フル版CSVのタグ検証(concernTags/sceneTags)は「**現在有効な語彙**」(FR-5参照)に対して行う

### FR-4: 読み込みデータの端末内保存(localStorage)

- 取り込み成功時、商品データ+語彙+ファイル名+取り込み日時を localStorage(ブラウザ内の保存領域)へ保存する。**次回アプリを開いたとき自動で復元**される
- 保存キー・データ形式はバージョン番号を含める(将来の形式変更で壊れた読み込みをしないため)。JSON解釈失敗・バージョン不一致の保存データは黙って無視し、内蔵デモデータで起動する
- 「デモデータに戻す」で内蔵の商品100件+内蔵語彙に戻り、**保存データも削除**する
- 保存失敗(容量超過等)の場合: 取り込み自体は成功として続行し、「端末への保存はできませんでした(次回開くと消えます)」旨の表示を出す
- 外部送信ゼロの原則は不変(localStorageは端末内のみ)

### FR-5: 語彙の状態管理

- アプリは「現在有効な語彙」を1つ持つ。初期値=内蔵 `vocab.json`
- かんたん版v2の読み込み成功 → 商品と語彙を**同時に**置き換える
- フル版CSVの読み込み成功 → 商品のみ置き換える(検証は現在有効な語彙に対して行う)
- デモに戻す → 商品・語彙とも内蔵へ戻す
- ナビ(質問2=場面、質問3=困りごと)・シーン絞り込み(FR-7)・場面の自動導出は、すべて現在有効な語彙に追随する(`questions.ts` の vocab.json 静的参照は現在有効な語彙参照へ改める)

### FR-6: 商品名キーワード検索

- 新設ページ `/search`。Homeに「商品名からさがす」導線を追加する
- 検索対象: 商品名(name)・メーカー(maker)・TAISコード(taisCode)の**部分一致**。入力のたびに即時絞り込み
- 正規化は「前後空白除去+英字の大文字小文字無視」のみ(全角半角変換・かなカナ変換はスコープ外)
- 検索結果は既存の商品カード(ProductCard)で表示し、タップで詳細へ。入力が空のときは案内文、0件のときは既存のEmptyStateを表示
- 現在有効な商品データ(デモ/取り込み済み)が検索対象

### FR-7: 分類内のシーン絞り込み

- ProductList(ジャンル内リスト)の絞り込みUIに「**場面**」を追加する(選択肢=現在有効な語彙の全場面+「すべて」。単一選択)
- 選択した場面を sceneTags に含む商品だけに絞る。既存の並べ替え・価格帯・保険区分と組み合わせ可能
- ご意見の例(〈歩行器〉家の中で使用/買物で使用)は、この「分類で開く→場面で絞る」導線で実現する

### FR-8: 商品詳細画面の拡充

- **メーカー**: 既存表示を維持(空・"―" はそのまま表示)
- **TAISコード**: 詳細画面に表示行を追加。値が空の商品では行ごと非表示(デモ100商品はTAISコードなしのため表示されない)
- **仕様**: 既存のspecs表を維持(かんたん版v2の仕様列もここに表示される)
- **類似商品(自動表示)**: 詳細画面下部に「似ている商品」節を新設
  - 抽出規則(決定論・入力の手間ゼロ): 同じ分類(genre) かつ 共通する困りごとタグ(concernTags)が1つ以上ある商品。スコア=共通困りごと数
  - 並び: スコア降順 → popularity降順 → id昇順。**上位3件**。自分自身は除外
  - 該当0件なら節ごと非表示。カード表示でタップすると当該商品の詳細へ遷移

### FR-9: 配布向けの文言・ドキュメント改訂

- アプリ内文言: 「自社データで試す」「自社のCSVを読み込んでテストプレイ」等の**事業者テストプレイ前提の文言**を、個人利用者向け(例:「自分の商品データを読み込む」)へ改める。保存されること(端末内のみ・外部送信なし)も ImportPage 上で明記する
- `docs/依頼元向けキット/かんたん版記入手順書.md`: 10列構成・シーン設定シートの編集手順(シーンの追加のやり方)・保存仕様を反映して改訂
- `docs/依頼元向けキット/CSV記入手順書.md`: 16列構成を反映して改訂
- `README.md`・`public/guide.html`: v2の変更点をテキストで反映(guide.html のスクリーンショット再撮影は**スコープ外**)
- `CLAUDE.md`: 設計書参照の記述を新設計書(v2)に合わせて更新
- 文書中の「依頼元」呼称は「利用者」系へ統一

## 4. 非機能要件

| 項目 | 要件 |
|---|---|
| 外部通信 | ゼロを維持(fetch/XHR等の通信コードを書かない。読み込み・保存はすべて端末内) |
| 追加パッケージ | **なし**(既存の fflate / react 系のみ。npm audit 0件を維持) |
| セキュリティ | `dangerouslySetInnerHTML` 禁止 / セル由来文字列はReactテキストノード描画のみ / zip爆弾対策・上限10MB・1,000行は既存仕様を維持 / 実在の商品・価格データをリポジトリに含めない |
| テスト | 新規ロジック(シーン設定シート解釈・10列検証・16列検証・類似商品抽出・検索絞り込み・保存の復元/破損無視)にVitestユニットテストを追加。既存テストは回帰なし(全パス維持) |
| ビルド | `npm run build`(tsc --noEmit && vite build)エラーなし |
| PWA | sw.js のプリキャッシュ対象を更新し、キャッシュ名を v4 に更新 |
| UI | スマホ優先・大ボタン・平易な日本語の既存方針を維持 |

## 6. 受入条件(全項目を満たしたら完了)

1. v2ひな形(.xlsx)をアプリからダウンロードでき、Excelで開くと10列+シーン設定シートがあり、分類・困りごと・誰が使うがプルダウン選択できる(**人間チェックポイント: Excelでの目視確認**)
2. シーン設定シートに新しい場面と困りごとを追加して記入した .xlsx を読み込むと、ナビの質問2・質問3、リストの場面絞り込み、場面の自動導出のすべてに新シーンが反映される
3. 読み込み成功後、ブラウザを閉じて開き直してもデータと語彙が復元される。「デモデータに戻す」で内蔵100商品+内蔵語彙に戻り、保存データも消える
4. `/search` で商品名・メーカー・TAISコードの部分一致検索ができる
5. ジャンル内リストで場面による絞り込みができる
6. 詳細画面にメーカー・TAISコード(空なら非表示)・仕様・類似商品(上位3件・自動)が表示される
7. 16列のフル版CSVが読み込める。旧形式(15列CSV・7列ひな形)は案内つきエラーで拒否され、既存データが維持される
8. 不正入力(見出し改変・価格に文字・語彙外の困りごと・困りごと重複のシーン設定)が行番号つきエラーで拒否される
9. `npm run build` 通過・`npm test` 全パス・`npm audit` 0件
10. 手順書2点・README・guide.html・CLAUDE.md・アプリ内文言がv2の内容と一致している
11. スマホ実機で「ひな形記入→読み込み→再起動で復元→検索・絞り込み」が完了できる(**人間チェックポイント**)

## 7. 実装上の制約(自律実装ルール)

- `.env` には触れない(本プロジェクトは `.env` が存在しないことが正)
- 既存ファイルの削除はしない
- `git add` / `git commit` はしない(人間が `git status` 確認のうえ実施)
- 設計書は `docs/design.md` へ書く。既存の design.md(案件版v1)・design-かんたん版.md はgit履歴に残るため**上書き・注記追記してよい**。新 design.md 冒頭に「v2(知人配布版)。旧版はgit履歴参照」と明記する
- 人間チェックポイント(受入条件1・11、および最終コミット・push・Pages反映)はパイプラインの対象外とし、完了報告で人間への依頼事項として列挙する
- 本書にない機能を追加しない
